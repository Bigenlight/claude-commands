# sleep-log

삼성헬스 갤럭시핏3 수면 스크린샷 → **vision 인식** → (1) **그날 데일리 노트의 잠 블록**("어제 잠 시간 및 금일 컨디션 체크")을 채우고, (2) `02-areas/sleep-management/sleep-tracking.md`의 `## 기록표`에 한 줄 추가한다. 주별 스샷이면 데일리가 아니라 **baseline/주별 추세**로 라우팅. 원본 스샷은 `08-assets/<YYYY>/sleep/`에 감사용으로 보관.

> **페르소나: Theo 본인의 수면 로그 비서.** 지금은 **3주 baseline 추적 중** ← 목적은 만성부족 상태에서 진짜 수면필요량(TST) 찾기. 그래서 **숫자 정확성이 생명**. 스샷에서 읽은 값은 추세 판단의 원자료라 지어내면 데이터 오염됨. 못 읽으면 `?`로 두고 플래그, **숫자 절대 창작 금지**.

> **말투**: 프로젝트 CLAUDE.md 노트 스타일 — 한국어 구어체 반말, 기술용어 영어(TIB/TST/SpO2 등), `← ` 화살표 부연, `**굵게**` 핵심, `>` blockquote 주의. 격식체(`~합니다`) 금지.

## 런타임 원칙 (솔로)

- 이 스킬은 **서브에이전트/워크플로우 안 씀.** 스샷 인식 + 파일 2곳 갱신은 사소·기계적 작업이라 **메인 Claude가 직접** 처리한다 (글로벌 규칙: 사소한 작업에 멀티에이전트 남발 금지).
- 대신 **정확성 self-check 의무**: 파일에 쓰기 **직전에** 쓸 각 값을 한 번 더 이미지와 대조해서 재확인. 특히 **시:분 숫자 · %/분 변환 · 점수 · 날짜** 4종은 이미지↔텍스트 1:1 대조 후 기록.

> **변수 처리 방식**: Claude Code Bash는 호출마다 새 셸이라 env가 다음 호출로 안 넘어간다. `REPO`, `TODAY`, `WAKE`, `DAILY_MD`, `TRACK_MD`, `ASSET_DIR` 같은 값은 **메인 Claude가 자기 컨텍스트(텍스트)에 기억**하고, 이후 모든 Bash/Edit 호출에 **절대경로/실제값을 직접 박아 넣는다.** 아래 코드의 `$VAR`는 가독성용이고 실제로는 절대값으로 치환.

## 권장 실행 시점 (당일 mutable 필드 주의)

- **지난밤 수면 수치(TST·단계·점수·효율·회복·SpO2)는 기상 순간 확정** ← 아침에 찍든 밤에 찍든 값 동일. 언제 넣어도 안전.
- **당일 지나며 변하는 필드는 딱 2개**: 표 `교란` 칸 안의 `운동O/X`(아침 `[ ]`→저녁 `[x]`) · `오후 컨디션`(낮 지나야 앎). + 롤링값(7일 평균·규칙성)은 참고라 무시.
- **블록의 `전날(M/D) O/X` 값은 안 바뀜** ← 이미 끝난 날의 운동이라 **아침 실행도 안전**. 블록엔 당일 운동이 아예 안 들어감 → 잠정인 건 **표 `교란` 칸 안의 `운동O/X` 쪽뿐**. 단 전제: **`WAKE-1` 데일리 노트가 있어야 전날 값을 읽음**(없으면 `전날?`, 3-5).
- **베스트 = 그날 밤 하루 마무리하며 1회 실행** ← 운동·오후 확정된 뒤라 한 방에 끝.
- **아침에 돌렸다면** → 객관 + 오전 각성 + 블록 `전날` 값은 확정으로 채워지고, 표 `운동`/오후만 잠정. 저녁에 **재실행(idempotent 갱신)** 하거나 그 두 칸만 손으로 채우면 됨 ← 재실행 시 운동 체크를 다시 읽어 갱신.

## 절대 원칙 (먼저 읽어라)

1. **숫자 지어내기 금지.** 못 읽은 값은 `?`로 두고 보고 시 플래그. "이 정도겠지" 추론 금지 ← 자릿수(분/시간/%) 한 자리 틀리면 데이터 오염.
2. **데일리 노트 임의 생성 금지.** 그날 노트 없으면 만들지 말고 사용자에게 물어본다.
3. **idempotent.** 같은 스샷 두 번 돌려도 블록/표 행이 중복 생성되면 안 됨 ← 이미 있으면 **갱신**, 없으면 **추가**.
4. **원본 스타일 보존.** 데일리 노트의 다른 섹션·이미지·코드·체크리스트는 절대 안 건드림. **잠 블록만** 만진다.

## 입력

1. **수면 스샷 이미지 1장 이상** (필수) — 대화에 첨부된 경로. 안 주면 물어본다. 같은 날을 상·하 스크롤로 2~3장 나눠 캡처한 경우도 흔함(→ 1-3 병합).
2. **주관 텍스트** (선택) — 기상방식/각성/컨디션/낮잠/한줄 소감. 있으면 그대로 사용, 없으면 3-4로 짧게 물어봄.

## Phase 0: 환경 + 변수 확정

### 0-1. 리포 루트 탐색 (없으면 중단)

PC마다 clone 위치가 다르므로 후보를 순서대로 탐색해 **존재하는 첫 경로**를 `REPO`로.

```bash
for cand in \
  "$HOME/For-Neural-Network-Improvement-Private-" \
  "$HOME/OneDrive/Desktop/For-Neural-Network-Improvement-Private-" \
  "$HOME/Desktop/For-Neural-Network-Improvement-Private-"; do
  if [ -d "$cand" ]; then REPO="$cand"; break; fi
done
[ -z "$REPO" ] && { echo "[FAIL] 리포 디렉토리를 못 찾음. clone 위치 확인 필요."; exit 1; }
echo "REPO=$REPO"
```

- 못 찾으면 자동 생성하지 말고 사용자에게 알리고 종료.

### 0-2. 오늘 날짜 + 주요 경로

```bash
TODAY=$(date +%Y-%m-%d)          # 예: 2026-07-10
echo "TODAY=$TODAY"
TRACK_MD="$REPO/02-areas/sleep-management/sleep-tracking.md"
test -f "$TRACK_MD" && echo "[OK] tracking 존재" || echo "[WARN] tracking 없음 — 경로 확인"
```

- `TRACK_MD` 없으면 임의 생성 금지 ← 사용자에게 알리고, 데일리 블록만 진행할지 물어본다.
- provenance 폴더: `ASSET_DIR="$REPO/08-assets/<YYYY>/sleep"` ← 연도는 **WAKE date 연도**로.

## Phase 1: 스샷 인식 (vision) + 종류 판별

### 1-1. 입력 스샷 확보

- 대화에 첨부된 이미지 경로를 전부 모은다 (1장 이상, 여러 장 가능).
- 각 이미지를 **Read 도구로 연다** (Read는 이미지를 시각적으로 보여줌).

### 1-2. 스샷 종류 자동 판별 — 일별 vs 주별

이게 라우팅을 가른다. 잘못 라우팅하면 표가 오염됨.

| 종류 | 화면 단서 | 라우팅 |
|------|-----------|--------|
| **일별** | 단일 날짜("오늘"/"7월 9일"), 취침–기상 **범위 1개**, 수면점수 N, **깊은/렘/얕은 단계 상세**, 회복%, SpO2 | → Phase 2~5 (데일리 블록 + 표 행) |
| **주별** | "주간 평균", 요일별 막대 그래프, **평균** 취침/기상, **규칙성 N/7**, 주 평균 TST | → Phase 6 (baseline/주별 추세, 표 행 추가 X) |

- 판별 애매하면(하이브리드 화면 등) 사용자에게 "이거 일별이야 주별이야?" 한 번 물어본다.
- 여러 장이 섞이면: 일별끼리는 각각 처리(다른 날일 수 있음), 일별+주별 섞이면 각각 라우팅.

### 1-3. 스샷 여러 장 병합 (같은 날 상·하 스크롤 캡처)

삼성헬스 일별 화면은 길어서 **한 날짜를 2~3장으로 나눠 캡처**하는 경우가 흔함(상단=점수·범위·단계, 하단=회복·SpO2·코골이).

- **같은 WAKE date로 판단되면** → 한 날짜의 필드를 여러 이미지에서 **모아 병합**. 절대 별개의 날로 두 행 만들지 말 것.
- 병합 판단 기준(다음 중 **2개 이상 일치**하면 같은 날): (1) 화면 상단 날짜 텍스트 동일, (2) 취침–기상 범위 동일, (3) 수면점수 동일.
- 서로 다른 날짜면 각각 독립 처리.

### 1-4. 필드 추출 — 삼성헬스 화면 요소 → 필드 대응표

화면 문구는 기기/버전마다 조금씩 다르니 **의미로 매칭**. 못 읽으면 `?`.

| 삼성헬스 화면 요소 (보이는 문구) | 추출 필드 | 형식/단위 | 비고 |
|---|---|---|---|
| 상단 날짜("오늘" / "7월 9일" / "어제") | **WAKE date** | `YYYY-MM-DD` | ★기상 날짜 = 데일리 노트 날짜. 최우선 |
| "오전 1:35 – 오전 7:48" 류 취침–기상 구간 | 취침–기상 범위 | `HH:MM–HH:MM` (24h) | 오전/오후(AM/PM) → 24h 변환 주의 |
| "수면 시간" X시간 Y분 | **TIB** (침대시간) | `XhYm` | 침대에 누워있던 총 시간 |
| "실제 수면 시간" X시간 Y분 | **TST** (실제수면) | `XhYm` | TIB보다 짧음. 헷갈리지 말 것 |
| 큰 숫자 점수 + "좋음/보통/나쁨" | 수면점수 + 등급 | `N(등급)` | 등급 라벨 그대로 |
| "숙면" 또는 "수면 효율" N% | 수면효율 | `N%` | |
| "깸" / "각성" N%(N분) | 깸 | `N%(N분)` | |
| "수면 주기" N회 | 수면주기 | `N회` | "(부족)" 등 라벨 있으면 같이 |
| 단계 "깊은 수면" N% / X분 | 깊은 | `N%(N분)` 또는 `N%(XhYm)` | 60분 기준(1-5 참고) |
| "렘 수면" N% / X분 | 렘 | 위와 동일 | |
| "얕은 수면" N% / X분 | 얕은 | 위와 동일 | |
| "신체 회복" N% | 신체 회복 | `N%` | "(낮음)" 등 라벨 있으면 같이 |
| "정신 회복" N% | 정신 회복 | `N%` | |
| "혈중 산소" / SpO2 평균 N% | SpO2 평균 | `N%` | |
| "90% 미만" 시간 | SpO2 90%↓ 시간 | `N분N초` 또는 `0초` | 없으면 `0초` |
| "코골이" 유무/시간 | 코골이 | `없음` / `N분` / (07-09처럼 없으면 생략 가능) | |
| (있으면) "지난 7일간 수면 시간" | 7일 평균 **수면시간(TIB 기준)** | `XhYm` | ⚠️**TST 아님** — 삼성헬스는 `수면 시간`=TIB / `실제 수면 시간`=TST로 구분하는데 이 카드 제목이 `수면 시간`이므로 **TIB 계열**. 2026-08-23 이전엔 "7일 평균 TST"로 오라벨했음 |
| (있으면) "수면 규칙성" N/7 | 규칙성 | `N/7` | |

### 1-5. 시간 포맷 변환 규칙 (촘촘하게)

삼성헬스는 한국어 "X시간 Y분" / "Y분"으로 표기됨. **아래로 통일 변환**:

- **"5시간 50분" → `5h50m`** · **"6시간 13분" → `6h13m`** · **"1시간 17분" → `1h17m`**
- **분만 있을 때(60분 미만) → `N분` 유지** (예: "42분" → `42분`, "21분" → `21분`)
  - 단계(깊은/렘/얕은) 표기: **60분 미만 → `N분`, 60분 이상 → `XhYm`** ← 기존 노트 관례
    (예: 깊은 42분 → `깊은 11%(42분)`, 렘 1시간17분 → `렘 20%(1h17m)`, 얕은 3시간51분 → `얕은 63%(3h51m)`)
- **TIB/TST**: 데일리 블록은 `XhYm`(m 포함, 예 `TIB 6h13m / TST 5h50m`), **표 칸은 `XhYY`(m 생략, 예 `5h50`·`4h58`)** ← 기존 07-09/07-10 관례 그대로.
- **시각(취침·기상)**: 24시간제 `HH:MM`, **분 앞 0 채우기**. 오전 1:35 → `01:35`, 오전 7:48 → `07:48`, 오후 11:20 → `23:20`.
- 범위 구분자는 **엔대시 `–`** (U+2013, 하이픈 `-` 아님. 기존 표 `02:30–07:41` 관례).

### 1-6. self-check (쓰기 전 필수)

Phase 2로 넘어가기 **전에** 추출한 전 필드를 이미지와 다시 대조:

1. **WAKE date** — 상단 날짜 맞나? "오늘" 스샷이면 오늘 아침 기상 → 오늘자 노트.
2. **취침·기상 HH:MM** — AM/PM 24h 변환 맞나, 0 채웠나. (자정 넘김 정상: 취침 01:35 < 기상 07:48)
3. **TIB ≥ TST** 인가 (아니면 뒤바뀜).
4. **점수 자릿수** + 등급 라벨.
5. **%/분 변환** — "시간 분" → `XhYm`, 60분 미만은 `N분`. 단계 %는 대략 검산(TST 5h50m=350분, 깊은 11%≈38분 → 화면 42분과 근사면 OK. 크게 어긋나면 다시 본다).

어긋나면 그 값을 `?`로 내리고 보고에 플래그.

## Phase 2: WAKE date → 데일리 노트 매핑

**WAKE date 기준**으로 그날 데일리 노트를 찾는다. "오늘" 스샷 = 오늘 아침 기상 → 오늘자 노트, "어제"/"7월 9일" 명시면 그 날짜.

### 2-1. 경로 탐색 순서

```bash
WAKE=2026-07-08   # Phase 1에서 확정한 절대값으로 치환
# ★주간 정리로 지난 데일리가 00-inbox로 옮겨지기도 하므로 여러 위치를 순서대로 탐색
DAILY_MD=""
for cand in \
  "$REPO/${WAKE}.md" \
  "$REPO/00-inbox/${WAKE}.md" \
  "$REPO/05-daily/${WAKE:0:4}/${WAKE:5:2}/${WAKE}.md"; do
  [ -f "$cand" ] && { DAILY_MD="$cand"; break; }
done
# 그래도 없으면 리포 전역 탐색(아카이브 제외) — 위치가 옮겨졌을 수 있음
[ -z "$DAILY_MD" ] && DAILY_MD=$(find "$REPO" -name "${WAKE}.md" -not -path '*/09-archive/*' 2>/dev/null | head -1)
echo "DAILY_MD=${DAILY_MD:-NONE}"
```

### 2-2. 둘 다 없으면 — 임의 생성 금지 (3옵션)

`DAILY_MD`가 비었으면 노트를 만들지 말고 `AskUserQuestion`으로:

> `2026-07-10` 데일리 노트가 아직 없어. ① 만들까?(기존 데일리 골격 + 잠 블록) ② `sleep-tracking.md` 기록표에만 추가할까? ③ 보류?

답에 따라:
- **"만들어"** → 기존 데일리 노트(예 `2026-07-09.md`) 골격 참고해 최소 스켈레톤 생성 후 진행.
- **"표만"** → Phase 4(표 append)만 수행.
- **보류/무응답** → 표 append만 하고 데일리 블록은 skip, 보고에 명시.

## Phase 3: 데일리 노트 잠 블록 쓰기 (핵심 — Edit anchor 안전하게)

목표 블록의 **골격(들여쓰기·줄 순서)만** `07-09`/`07-10` 노트 기준. **단 낮잠 라인은 그 노트들이 구포맷이라 복제 금지** ← 반드시 3-2 신포맷(`전날(M/D) O`)을 따를 것. (예외: 재실행(C)으로 구문안 노트를 만나면 3-3 (C)대로 **그 줄 보존**) `### 매일 할 일` 아래 "어제 잠 시간 및 금일 컨디션 체크" 체크박스 라인을 찾아 그 하위를 채우고 체크박스를 `[x]`로.

### 3-1. 먼저 Read + grep으로 현재 상태 판정 (Edit 전 필수)

`DAILY_MD`를 Read하고, 아래 3가지 상태 중 어디인지 판정:

```bash
grep -n "잠 시간 및 금일 컨디션" "$DAILY_MD"   # 라인 존재/번호 → 상태 A/B/C 판정
grep -n "객관 (갤럭시핏3"        "$DAILY_MD"   # 블록 이미 있으면 상태 C
```

- **(A) 잠 라인 없음** — 문구가 노트에 아예 없음 → 새로 삽입.
- **(B) 라인만 있고 블록 없음** — `- [ ] 어제 잠 시간 …`는 있는데 하위 `**객관**` 블록이 없음 → 라인 교체 + 블록 삽입.
- **(C) 이미 완성 블록 존재** — 하위에 `**객관 (갤럭시핏3 / 삼성헬스)**`가 이미 있음 → **중복 생성 금지, 갱신(idempotent)**.

> **anchor 유일성 원칙**: `grep -n`으로 라인 번호를 확인해 상태를 확정한 뒤 Edit한다. "있겠지" 가정으로 Edit 치지 말 것. Edit의 `old_string`은 **노트에 실제로 존재하는 문자열과 정확히 일치**하고 **유일**해야 한다. 유일하지 않으면 주변 컨텍스트를 더 포함해 확장.

### 3-2. 블록 포맷 (이 형식 그대로)

`?`인 필드는 `?`로 둔다. 주관 필드는 3-4에서 확보.

```
- [x] 어제 잠 시간 및 금일 컨디션 체크 → 3주 추적표: [[sleep-tracking]]
  - **객관 (갤럭시핏3 / 삼성헬스)**
    - 침대 HH:MM–HH:MM → **TIB XhYm / 실제수면(TST) XhYm** / 점수 N(등급)
    - 수면효율(숙면) N% · 깸 N%(N분) · 수면주기 N회
    - 단계: 깊은 N%(N분) / 렘 N%(NhNm) / 얕은 N%(NhNm)
    - 회복: 신체 N% · 정신 N% / SpO2 평균 N%(90%↓ 시간) · 코골이 …
    - 7일 평균 수면시간(TIB 기준) XhYm · 수면 규칙성 N/7 ← (스샷에 있을 때만, 회복 줄 바로 다음)
  - **주관 / 맥락**
    - 기상: [알람|자연] · 아침 각성도 N/5
    - <한줄 소감>
    - 낮잠 – (운동: **전날(M/D) O** ← 이 밤의 입력 · 당일은 위 `매일 할 일` 체크 → 내일 밤 입력)
```

- **대시(–)는 en-dash `–`(U+2013).** 기존 노트가 en-dash 씀. 미기입 낮잠은 `_`가 아니라 `–` ← 실제 낮잠값이 있으면 그 값 사용(예: `낮잠 15분(점심)`).
- 낮잠 라인의 **`전날(M/D) O/X`는 실제 값으로 채워 넣을 것** (예: `전날(8/9) X`) ← 값은 3-5 방식대로 `WAKE-1` 데일리의 운동 체크에서 읽음. 못 읽으면 `전날?` (지어내기 금지).
- **날짜 `(M/D)`는 반드시 같이 박을 것** ← 이 리포는 데일리를 전날 파일 `cp`로 만들어서 stale 복붙 사고가 실제로 여러 번 남. 날짜가 박혀 있으면 `전날(8/8)`처럼 안 맞는 게 즉시 눈에 띔(자기검증).
- `전날` 값은 **이미 끝난 날이라 안 바뀜** → 안전. 반면 `당일` 운동 체크는 저녁에 바뀌므로 그건 표(Phase 4) `교란(낮잠)` 칸 안의 `운동O/X`에서만 다룸 ← 표 헤더에 별도 `운동` 칸은 없음.
- **7일 평균 수면시간(TIB) · 규칙성 줄**은 스샷에 값이 보일 때만, **회복 줄 바로 다음**에 넣는다(실제 노트 순서: 단계 → 회복 → 7일 평균).
- 오후 컨디션은 블록엔 별도 칸 없음 ← 한줄 소감에 녹이거나 표(Phase 4)의 `오후` 칸에 반영.

### 3-3. 상태별 Edit 전략 (anchor 잡는 법)

**(A) 라인 자체가 없음** — `### 매일 할 일` 체크리스트에 삽입. 기존 노트는 `- [ ] 운동` 다음에 잠 라인이 오는 패턴 → 운동 라인을 anchor로 그 뒤에 블록을 붙인다. 운동 라인이 `[x]`인지 `[ ]`인지 먼저 grep으로 확인해 **실제 문자열 그대로** anchor로. 운동 라인이 없으면 `### 매일 할 일` 헤더 + 바로 아래 첫 항목을 함께 포함해 유일성 확보.

**(B) 라인만 있고 블록 없음** — 체크박스 라인 한 줄을 통째로 `old_string`으로 잡아 블록 포함(체크박스 `[x]`) 버전으로 교체. 라인 끝 문구(`→ 3주 추적표: [[sleep-tracking]]`)가 노트마다 다를 수 있으니 grep 결과의 **실제 라인 전체**를 복사해 anchor로.

**(C) 이미 완성 블록 존재 (재실행/갱신)** — 블록의 **첫 줄(체크박스 라인)부터 주관/맥락 마지막 줄(`낮잠 …`)까지** 통째로 `old_string`으로 잡고, `new_string`은 **객관 줄만 새 값 · 주관/낮잠 줄은 읽은 문자열 그대로 복사**해서 1회 교체 ← "통째 교체"와 "낮잠 라인 보존"은 이렇게 양립함: 낮잠 라인을 `old_string`에 **포함**하되 `new_string`엔 **그대로 되붙임**.
- **객관 수치만 갱신, 기존 주관은 보존** ← 사용자가 이미 손으로 적은 한줄 소감·각성도·낮잠을 덮지 말 것. 새 스샷에 주관 관련 새 정보가 없으면 주관 라인은 기존 그대로 두고 객관 라인만 교체. **단 `전날?`는 예외** — 첫 실행 때 `WAKE-1` 노트가 없어 `전날?`로 박혔다가 나중에 그 노트가 생겨 읽히면 **그 토큰만 갱신 OK**.
- 여러 번 잘게 Edit하는 것보다 **블록 통째 1회 교체가 안전**.
- ⚠️**과거 노트를 재실행할 때 낮잠 라인 문안을 신규 포맷으로 강제 변환하지 말 것.** (C) 갱신은 블록 마지막 줄(`낮잠 …`)까지 통째로 교체하는 방식이라, **2026-08-11 이전에 쓰인 구문안 노트를 재실행하면 그 노트만 조용히 신문안으로 갈아타는** 사고 남. 과거 데일리는 **역사 기록이라 소급 수정 안 하는 게 원칙** ← 구문안 낮잠 라인을 만나면 **그 줄은 있는 그대로 보존**(`old_string`엔 포함, `new_string`에 그대로 복사)하고 객관 수치 줄만 갱신할 것.
- **구문안 판별은 아래 리터럴 2종으로** ← 날짜 기준은 못 씀(노트에 작성일이 없고 전날 파일 `cp`로 만들어져서). 낮잠 라인에 둘 중 하나가 보이면 그 줄은 **손대지 말 것**:
    - ``(운동=위 `매일 할 일` 체크 참조)`` ← 대다수
    - ``(운동 O = 위 `매일 할 일` 체크)`` ← 07-09만 있는 변종
- **표(Phase 4)는 반대** ← 표 행은 이미 전체 소급 백필돼서, 과거 날짜 재실행이어도 신포맷(`전날` 포함)으로 갱신하는 게 맞음. **블록만 보존, 표는 갱신** — 이 비대칭은 의도된 것.

### 3-4. 주관 필드 확보

**물어볼 주관 5종**: 기상방식(알람/자연) · 오전 각성(1~5) · 오후 컨디션(1~5) · 낮잠 · 한줄 소감. (음주·카페인은 추적 안 함 ← 교란은 낮잠만)

1. **사용자가 텍스트로 이미 줬으면** 파싱해서 사용.
2. 안 줬으면 `AskUserQuestion`으로 **한 번에 짧게** 물어봄(마찰 최소화 — 여러 질문 묶어 1회).
3. 그래도 안 주면 **placeholder**: 각성도 `_/5`, 낮잠은 `–`, 한줄은 `<한줄 소감>` 그대로. 보고에 "주관 미기입, 나중에 채워라" 명시.

### 3-5. 운동 O/X 읽기 — ★**당일 + 전날 두 개** 읽는다 (블록/표 공용)

운동은 스샷에 없음 → **데일리 노트의 `- [x]/[ ] 운동` 체크 상태에서 읽어온다.**

> ★★**시간축 함정 (2026-08 수정, 반드시 지킬 것)**
> 표의 한 행 = **"그 날짜 아침에 기상한 밤"**의 수면. 근데 `WAKE` 데일리의 운동 체크는 **기상한 그날 낮**의 운동이라 **그 수면보다 나중에** 일어난 일 ← 그대로 한 값만 쓰면 **인과가 거꾸로** 박힘.
> 그래서 **`WAKE`와 `WAKE-1` 두 날의 체크를 다 읽어** **표에** `(운동O·전날X)` 형태로 기록한다 ← 블록 포맷은 이것과 다름(아래 "포맷이 블록/표에서 다름" 참고).
> - `운동` = WAKE 당일 낮 (사실 로그. **이 행 수면엔 영향 없음** — 다음 행 수면의 입력)
> - `전날` = WAKE-1 낮 ← **이 행 수면에 실제 영향을 준 값. 분석은 이쪽을 봄**

```bash
WAKE=2026-08-10        # 절대값으로 치환
PREV=$(date -d "$WAKE -1 day" +%F)   # 예: 2026-08-09
for D in "$WAKE" "$PREV"; do
  F=""
  for c in "$REPO/$D.md" "$REPO/00-inbox/$D.md" "$REPO/05-daily/${D:0:4}/${D:5:2}/$D.md"; do
    [ -f "$c" ] && { F="$c"; break; }
  done
  [ -z "$F" ] && F=$(find "$REPO" -name "$D.md" -not -path '*/09-archive/*' 2>/dev/null | head -1)
  echo -n "$D: "; [ -z "$F" ] && echo "NOTE_NONE(→ ?)" || grep -m1 -oE '^\s*- \[[ xX]\] *운동' "$F" || echo "운동라인없음(→ ?)"
done
```
- **`M/D` 변환 주의**: 위 bash의 `PREV`는 `2026-08-09`(zero-pad·하이픈) ← 블록에 넣을 땐 `전날(8/9)`로 **zero-pad 빼고 슬래시**로 변환할 것. `전날(08/09)` 금지.
- `- [x] 운동` → **O**, `- [ ] 운동` → **X**. 운동 라인/노트 자체가 없으면 **`?`** (지어내지 말 것).
- **결과를 쓰는 포맷이 블록/표에서 다름 (주의)** ← 아래 `(운동O·전날X)`는 **표(Phase 4) 전용** 포맷. 블록(3-2)은 `전날(M/D) O` 포맷이라 완전 다름 — 3-5만 보고 블록에 표 포맷 박지 말 것:
    - 표 `교란` 칸: `낮잠15 (운동O·전날X)` ← 날짜 없음, 당일+전날 둘 다
    - 블록 낮잠 라인: `낮잠 – (운동: **전날(8/9) O** ← …)` ← 전날만, 날짜 `(M/D)` 필수
- 표 `교란` 칸 = `낮잠N (운동O·전날X)` / `– (운동X·전날O)` ← **두 값 항상 같이**. `전날` 빠뜨리면 분석축이 통째로 어긋남.
- **카페인·음주는 추적 안 함** (Theo가 거의 안 함) ← 블록·표에 문구 넣지 말 것. 교란은 **낮잠만**.

> ⚠️**운동 체크는 하루 중 바뀜** (아침 `[ ]` → 저녁 `[x]`). **08-06·08-10 두 번 사고 남** ← 낮에 돌려서 `운동X`로 박혔는데 그날 저녁에 운동함 → 표가 틀린 채로 며칠 방치됨. **규칙 세운 그 주에 또 재발했음** ← 경고문으론 못 막으니 실행 시점을 밤으로 옮기는 게 진짜 방어.
> → **하루 마무리하며 1회 실행이 베스트.** 아침에 돌렸으면 밤에 **재실행**할 것. 보고에 "운동=현재 체크 기준(저녁 재확인 필요)" 명시.
> 반면 `전날` 값은 이미 하루가 끝난 날이라 **안정적** ← 이게 분석축인 게 다행인 지점.

## Phase 4: 기록표 append (sleep-tracking.md)

`## 기록표`의 표에 **한 줄 추가**. 위치·중복·갱신을 엄격히.

### 4-1. 먼저 표 상태 파악

```bash
MMDD=07-10   # WAKE date의 월-일로 치환
grep -n "^| ${MMDD} " "$TRACK_MD"   # 같은 날짜 행 이미 있나 → 있으면 갱신
grep -n '`\*깊은`'    "$TRACK_MD"   # 각주 라인(표 끝 경계) 위치
```

- **행 위치**: 표의 **마지막 데이터 행 다음**, 그리고 ``> `*깊은` `` 각주 라인 **앞**.
- **중복 방지**: `| MM-DD |`로 시작하는 행이 이미 있으면 새 행 추가 금지 → 그 행을 교체(갱신).
- **같은 날짜가 이미 2행**이면(비정상) 사용자에게 알리고 **멈춘다**.

### 4-2. 행 포맷

기존 표 헤더:
`| 날짜 | 취침–기상 | TST | 기상 | 오전 | 오후 | 교란(낮잠) | 참고(효율/깊은*/점수) | 한줄 소감 |`

```
| MM-DD | HH:MM–HH:MM | XhYY | 알람 | 오전 | 오후 | 낮잠N (운동O·전날X) | 효율% / 깊은분 / 점수 | 한줄 |
```

실제 행 예시(그대로 맞출 것 — `/` 양옆 공백, 미기입은 en-dash `–`):

```
| 07-09 | 02:30–07:41 | 4h58 | 알람 | 2 | 2→회복 | 낮잠15 (운동O·전날X) | 96% / 21분 / 71 | 오전 피곤, 오후 헤드뱅잉, 낮잠 15분에 회복 |
| 07-10 | 01:35–07:48 | 5h50 | 알람 | 3 | ? | – (운동X·전날O) | 94% / 42분 / 83 | 아침 나쁘지 않음(어제보단), 최고각성은 아님 — 흐림 탓? |
```

- `MM-DD` = WAKE date의 월-일 (예 `07-10`).
- **`기상` 칸 = `알람`/`자연`/`환경` (택1)** ← **파이프 `|` 절대 금지.** `|`를 리터럴로 쓰면 마크다운 표 컬럼이 깨짐. 실제 07-09/07-10 행처럼 **값 하나만**(`알람`) 들어감.
- `TST` 칸 = `XhYY`(m 생략, 예 `5h50`).
- `교란` 칸 = `낮잠N (운동O·전날X)` 또는 `– (운동X·전날O)` ← 미기입 낮잠은 en-dash `–`. **`·전날O/X`는 3-5 규칙대로 반드시 같이 넣을 것** (WAKE-1 데일리에서 읽음, 못 읽으면 `전날?`).
- `참고` 칸 = `효율% / 깊은분 / 점수` (예 `94% / 42분 / 83`).
- 못 읽은 값은 `?`.

### 4-3. Edit anchor (표)

- **삽입 위치 = 날짜순 유지 (중요).** 표는 날짜 오름차순. 먼저 `grep -n "^| [0-9]" "$TRACK_MD"`로 기존 행 날짜를 파악하고:
  - 새 날짜가 **기존 최신 행보다 뒤(미래)** → 마지막 데이터 행 뒤(각주 앞)에 append. `old_string` = 마지막 행 전체(+빈 줄+각주 리드 ``> `*깊은` …``)로 유일성 확보, 그 뒤에 새 행 삽입.
  - 새 날짜가 **중간/과거(백필)** → 자기보다 날짜가 **큰 첫 행**을 anchor로 그 **앞에** 삽입 (`new_string` = `새 행\n그 행`). 예: 07-08 백필 → 07-09 행 앞에.
  - 엉뚱한 데 끼우는 사고 방지 위해 anchor 행 전문은 Read/grep으로 정확히 복사.
- **갱신**: 그 `| MM-DD | … |` 행 **한 줄만** `old_string`(기존 전체)→`new_string`(새 값)으로 교체. 날짜 칸이 유일 키라 안전.

## Phase 5: 스샷 provenance 저장

원본 스샷을 감사·검증용으로 보관. **데일리 노트에 인라인 임베드는 안 함**(노트 깔끔 유지).

```bash
mkdir -p "$REPO/08-assets/${WAKE:0:4}/sleep"
cp "<스샷1 경로>" "$REPO/08-assets/${WAKE:0:4}/sleep/${WAKE}.jpg"
# 같은 날 2장 이상이면 suffix:
cp "<스샷2 경로>" "$REPO/08-assets/${WAKE:0:4}/sleep/${WAKE}-2.jpg"
```

- 확장자는 원본 따라 `.jpg`/`.png`. 연도는 WAKE date 기준. 재실행 시 같은 이름 덮어쓰기 OK(동일 원본).

## Phase 6: 주별 스샷 처리 (일별 아닐 때)

주별이면 **데일리 행/블록을 만들지 않는다.** `sleep-tracking.md`의 요약을 **값만** 갱신/추가.

- 대상: `## 출발점 (baseline)` 섹션(평균 TST·평균 취침/기상·규칙성 대조용) **또는** 없으면 `## 기록표` 위에 `## 주별 추세` 가벼운 섹션 신설해 표/불릿으로 누적.
- 갱신 내용: 주 구간(예 `07-05~07-11`), 주 평균 TST(`XhYm`), 평균 취침/기상 시각, 규칙성 `N/7`.
- **baseline의 "올해 초 4개월 평균" 기준값은 함부로 덮지 말 것** ← 새 주 데이터는 별도 줄/행으로 추가해 대조가 되게.
- Edit anchor: baseline 섹션 마지막 blockquote(`> 이게 추적 시작 전 기준선 …`) 또는 `## 프로토콜` 헤더를 경계로 그 사이에 삽입.
- 주별 provenance: `08-assets/<YYYY>/sleep/weekly-YYYY-MM-DD.jpg`(주 종료일 기준).

> 주별은 라우팅이 애매할 수 있으니, 어디에 뭘 쓸지 **먼저 사용자에게 한 줄 확인**하고 반영해도 좋다(baseline 오염 방지).

## Phase 7: 보고

인식·기록 결과를 표로 요약:

- **인식한 값 표** (필드 / 값 / 못 읽음 여부) — `?` 항목은 **못 읽음 플래그**로 강조.
- **어디에 뭘 썼나**: 데일리 블록(경로 + 상태 A/B/C 중 뭐였는지), 표 행(추가/갱신), provenance 저장 경로.
- 운동은 **당일·전날 두 값 각각** 어느 노트에서 읽었는지 명시 (`WAKE.md` → 당일, `WAKE-1.md` → 전날). 운동 라인 없었으면 플래그. **`WAKE-1` 노트가 없어 `전날?`가 됐으면 반드시 플래그** ← 나중에 노트 생기면 그 토큰만 갱신 가능(3-3 C).
- 주관 placeholder(`–`/`_/5`) 남았으면 "나중에 채워라" 안내.
- 마지막에 **"git 추적 파일이니 원하면 커밋"** 안내(자동 커밋 안 함. 원하면 `git-pull-push` 스킬 호출 가능).

## 엣지케이스 요약

- **데일리 노트 없음** → 생성 여부 물어봄(임의 생성 금지). 표만/보류 옵션 제공(2-2).
- **재실행 중복** → 블록/행 이미 있으면 추가 아닌 **갱신**. 상태 A/B/C 판정 후 Edit(3-1).
- **잠 블록 이미 존재(C)** → 객관만 갱신, 사용자가 적은 주관은 보존.
- **표에 같은 날짜 행** → 그 행만 교체. 같은 날짜 2행이면 **멈추고 보고**.
- **`기상` 칸 파이프 금지** → `알람`/`자연` 값 하나만(4-2).
- **스샷 여러 장** → 같은 날이면 필드 병합(한 행/한 블록), 다른 날이면 각각(1-3).
- **주별 스샷** → 데일리 아닌 baseline/주별 추세로 라우팅, baseline 기준값 덮지 말 것.
- **값 못 읽음** → `?` 유지, 지어내기 금지, 보고 플래그.
- **운동은 당일+전날 2일치 읽음**(3-5) → 블록은 `전날(M/D) O/X`만 표기, 표는 `(운동O·전날X)` 둘 다.
- **`WAKE-1` 노트 없음** → `전날?`(지어내기 금지) + 보고 플래그. 나중에 노트 생기면 그 토큰만 갱신 OK(3-3 C).
- **과거 노트 재실행** → 구문안 낮잠 라인은 **그대로 보존**(리터럴 2종으로 판별, 3-3 C). 표 행은 반대로 신포맷 갱신.
- **"오늘" vs 명시 날짜** → "오늘"=`TODAY`, 명시 날짜는 그 날짜로 매핑.
- **en-dash(–) 통일**, 미기입 낮잠도 `–`. self-check(TIB≥TST, 단계 %합≈100) 통과 후에만 쓰기.
